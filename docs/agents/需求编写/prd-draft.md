# PRD: 用户注册登录功能

## 1. 背景

用户服务（user-service）作为 cyber-sdlc v0.1.0 的核心模块，需要提供基础的身份认证能力。当前系统无任何认证机制，用户无法创建账户或安全地访问受保护资源。

本次需求实现用户注册与登录的基础认证流程，确保：
- 用户可以通过邮箱+密码创建账户
- 用户可以通过密码登录获取会话
- 用户可以选择"记住我"以减少重复登录操作
- 密码在存储和校验环节满足基本强度要求，防止弱口令攻击

## 2. 用户故事

- 作为**新用户**，我希望通过邮箱和密码注册账户，以便后续登录使用系统
- 作为**已注册用户**，我希望通过邮箱和密码登录，以便访问受保护的系统功能
- 作为**已登录用户**，我希望勾选"记住我"后 7 天内无需重新登录，以便减少重复操作
- 作为**新用户**，我希望注册时获得密码强度的实时反馈，以便设置更安全的密码
- 作为**系统管理员**，我希望密码以不可逆方式存储，以便即使数据库泄露也无法还原明文密码

## 3. 验收标准

### 注册

- [ ] 注册接口接收 `email` + `password` 两个字段
- [ ] 邮箱格式校验：不合法的邮箱格式（如缺少 `@`、缺少域名）返回明确的错误提示
- [ ] 邮箱唯一性校验：已注册的邮箱再次注册时返回 `409 Conflict` 错误
- [ ] 密码强度校验（注册时强制要求）：
  - 最少 8 字符，最多 64 字符
  - 至少包含以下四类中的三类：大写字母、小写字母、数字、特殊字符
  - 密码强度不满足时返回具体不满足的原因（如"密码至少需要 8 位"）
- [ ] 密码不可明文存储，必须经过单向哈希处理（具体算法由架构师决定）
- [ ] 注册成功后返回用户基本信息（用户 ID、邮箱），不返回密码相关字段
- [ ] 注册成功后自动创建会话（用户无需再手动登录一次）

### 登录

- [ ] 登录接口接收 `email` + `password` 两个字段
- [ ] 登录成功后返回有效的会话凭证（token / session）
- [ ] 邮箱或密码错误时返回统一的 `401 Unauthorized` 错误，不区分"邮箱不存在"和"密码错误"（防止枚举攻击）
- [ ] 连续登录失败超过一定次数后进行限流（具体阈值由架构师决定）

### 记住我

- [ ] 登录接口接收可选的 `remember_me` 布尔字段
- [ ] `remember_me = true` 时，会话有效期设为 7 天
- [ ] `remember_me = false`（默认）时，会话有效期设为短期（具体时长由架构师决定，建议 1-24 小时）
- [ ] 会话过期后需要重新登录

### 密码强度校验

- [ ] 密码强度校验逻辑在注册和修改密码场景复用（同一套规则）
- [ ] 密码强度校验在前端实时反馈 + 后端二次校验（双重保障）

## 4. Scope（范围）

### In scope（v0.1.0 做）

- 邮箱+密码注册
- 密码登录（邮箱 + 密码）
- "记住我"功能（7 天免登录 vs 短期会话）
- 密码强度校验（规则 + 反馈）
- 密码单向哈希存储
- 会话凭证签发与过期管理

### Out of scope（v0.2+ / 不做）

- 第三方登录（OAuth / Google / GitHub 等）
- 邮箱验证（注册后发邮件确认）
- 密码重置 / 忘记密码流程
- 双因素认证（2FA / TOTP）
- 账户锁定 / 封禁管理
- 用户资料管理（头像、昵称修改等）
- 多设备会话管理（查看/踢出其他设备登录）
- 验证码（图形验证码 / 短信验证码）

## 5. UI/UX 期望

> 本需求以 API 接口为主，前端交互流程供参考。

### 注册页面

- 表单字段：邮箱、密码、确认密码
- 密码输入框旁实时显示强度指示器（弱/中/强），并提示不满足的具体规则
- 提交后：成功 → 跳转至已登录状态；失败 → 表单上方显示错误信息，保留邮箱输入

### 登录页面

- 表单字段：邮箱、密码
- "记住我"复选框（默认不勾选）
- 提交后：成功 → 跳转至主页；失败 → 提示"邮箱或密码错误"

## 6. 非功能需求

### 性能

- 注册接口响应时间 < 500ms（含密码哈希计算）
- 登录接口响应时间 < 200ms

### 安全

- 密码单向哈希存储，不可逆（具体算法由架构师决定，建议 bcrypt / argon2）
- 登录错误信息不区分"邮箱不存在"和"密码错误"
- 密码强度校验前后端双重保障（前端可被绕过，后端必须校验）
- 会话凭证应防篡改、防重放（具体机制由架构师决定）
- 密码相关字段不出现在任何 API 响应中

### 兼容性

- API 遵循 RESTful 规范，JSON 交互
- 前端兼容 Chrome 100+ / Firefox 100+ / Safari 15+
